### 0.1 What the research changed about the charter's own picture

Four findings move work into wave 1 that the charter text does not name, and one moves work out.

1. **The composition seam throws structure away — in two places, not one.** `load_rule` returns a
   structured `LoadError` with a real `spec_code()` (`rule_pipeline.rs:108-188`), and its
   `Intrinsic(DeclError)` variant genuinely preserves the wrapped struct (`:139`). But:
   - `prepare_rules` is `pub(crate)` and returns `Result<PreparedRules, String>`
     (`babylon-tick/src/lib.rs:136` through the return type at `:145`) — private, prose-only, and
     first-failure-only. Worse, it **mints one code of its own in prose**: a raw
     `return Err(format!("E-LOAD-001: {qname} is the implicit <edge-type>/strength field (D32) …"))`
     at `lib.rs:203-211`, which no structured error type ever sees.
   - `ScenarioError` (`scenario.rs:69-76`) carries only `{message, code}`, and its conversion impls
     **flatten every wrapped type's identity**: `From<ReadError>` destroys the byte offset into
     prose (`:89-99`), `From<GraphError>` (`:101-108`) and `From<VocabularyError>` (`:110-121`)
     discard six variants' worth of typed fields, and `load_defenum`'s inline
     `.map_err(|e| ScenarioError { code: e.spec_code(), message: e.to_string() })` (`:942-949`)
     throws away a `DeclError::Duplicate{name, what}` that started out fully typed.

   Revision 1 named only the first bullet and only its privacy/stringification half. Both bullets
   are the same defect and both are wave-1 work (Tasks 2 and 3). Without the second, essentially
   **every `.bscn` diagnostic** — the exact surface Task 8 spends the wave's largest budget
   documenting — would have no identity to locate and would ship at file level.
2. **A `.bsl` rule pack cannot be typechecked alone.** Every registry is scenario-side: `types`
   from the scenario's `deffield`s (`babylon-tick/src/lib.rs:190-218`), `vocabulary_registry`
   (`:358`), `enums` (`:382`), ceilings from the scenario's actual census (`:248-261`).
   `rg 'defenum|defvocabulary|deffield' rust/crates/babylon-tick/content/rules/*.bsl` returns
   nothing. Pair resolution is therefore wave-1 work and `interFileDependencies: true` is correct
   from day one. **Honest framing** (revision 1 oversold this): the manifest is not what makes wave
   1 *correct* — §6.3's unpaired-file path is honest with or without it — it is what makes wave 1
   *useful*, by turning a rule pack's diagnostics from "lexical and structural only" into the full
   staged pipeline. Plus the `[orphans]` table, which makes #646's landmine visible.
3. **The span table is not what makes E-LEX precise.** `ReadError.position` already exists
   (`reader.rs:227-234`) and `read_all` already re-bases it past a BOM (`:262-279`), so E-LEX spans
   need only a server-side line index. The span table's wave-1 job is narrower: it is what turns a
   **typed identity** (finding 1) into a **range**, without ever reading a location out of prose
   (§6.2). Building it now is right — every wave-2 capability is blocked on it — but the payoff is
   stated at its real size.
4. **Out:** tree-sitter is **not** a wave-1 dependency of `babylon-ls`. The reader's own spans are
   strictly more precise and come from the one brain; tree-sitter's value (highlighting, folding,
   outline) is wave 2, and its generated parser is a git-ignored build product
   (`tools/tree-sitter-bsl/README.md:32,51-52`) with no CI gate — pulling it into `rust:check`
   would make a fresh clone's Rust build depend on `tree-sitter generate`. The D93 grammar work
   (Task 8) still lands in wave 1; it lives in `tools/` and `docs/`, not in the server.

### 0.2 The founding constraint, restated as a testable law

> **One brain.** `babylon-bsl` (with `babylon-tick`'s registry assembly) decides **what is wrong**
> and **what the offending thing is called**. `babylon-ls` decides **where to draw the squiggle**,
> and nothing else. The server mints no code, re-implements no check, and **never parses an
> identity out of an error message's prose**. When it cannot locate a form, the diagnostic degrades
> to file level — never to silence, never to a guess.

Note the clause revision 1 lacked: *naming the offending thing is the loader's job too.* That is
what `ErrorIdentity` (§2.3) exists for, and it is why the server needs no knowledge of the 52 error
variants behind it.

**Five** mechanical guards hold this law, all specified in Task 7 and all mutation-validated:

| # | Sentinel | Bans |
|---|---|---|
| 7.1 | E-code literal | any full `E-<FAM>-NNN` literal under `babylon-ls/src/**` (family prefixes allowed) |
| 7.2 | No prose-parsing | the `regex` crate, and `.contains(`/`.split(`/`.find(` applied to an error message |
| 7.3 | Read-only | `fs::write`/`File::create`/`OpenOptions`/`remove_file` outside the log-sink module |
| 7.4 | Determinism | `SystemTime::now`/`Instant::now`/`rand` outside the log-sink module |
| 7.5 | Layering | any other crate's `Cargo.toml` naming `babylon-ls` |

The precision-class conformance rows (Task 6.1, `tests/diagnostics_conformance.rs`) are a
**different** artifact — a behavioral contract, not a sentinel. Revision 1 miscounted them into
this list; they have their own row in §5.3's table.

## 1. Global constraints

Non-negotiable for every task below.

1. **Non-normative, observes-only.** The server holds no state the loader does not, never writes
   content, and is never a gate. A file it likes may still be refused at load, and the load path
   stays the only door (#533's load-ceremony rule).
2. **Determinism.** Same (workspace text, manifest) ⇒ same diagnostics, byte for byte, in the same
   order. No wall-clock, no OS entropy, no `HashMap` iteration feeding output order. Two explicit
   carve-outs, both outside the contract and both stated where they occur: the log file's
   timestamps (Task 5.5) and the protocol test's watchdog (§5.3), which can only convert a hang
   into a failure and can never change a diagnostic. The P15 Gauntlet lesson — wall-clock in a
   *pass/fail* condition is determinism poison — is respected: neither carve-out gates a pass.
3. **No engine behavior change.** Tasks 1–3 touch `babylon-bsl`/`babylon-tick`; every tick golden
   and every CAS pin (§2.4) must stay byte-identical. Movement is a STOP, never expected drift.
4. **No new E-codes, no new form tags, no new mathematics.** This train documents and surfaces what
   exists. The `.bscn` chapter (Task 8) cites `E-LOAD-044/052/054/055/056/057` — all six already in
   `bsl-language.rst` (`:1080`, `:2586`, `:483-484`, `:2240-2241`, `:2260`, `:3179`) — and mints
   none.
5. **TDD, red phase mandatory.** Every task is written failing-test-first. A red step is a commit
   whose test fails and whose message says so, immediately followed by the green commit. Commit per
   unit of work via `mise run commit -- "type(scope): msg"`.
6. **Power-of-10 rules.** Explicit typing, no catch-alls, ≤~100 lines per function, **every loop
   statically bounded**, smallest possible scope. Note the rule bounds *iterations*, not *waits* —
   §5.3's protocol harness needs both, and specifies both.
7. **Clippy pedantic from day one.** `babylon-ls` joins the per-crate pedantic legs in `rust:check`
   (`.mise.toml:1635-1652`) alongside kernel/bsl/graph — `-D warnings -D clippy::pedantic`, plus
   the workspace-wide `-D clippy::cognitive_complexity` (threshold 25, `rust/clippy.toml:8`) and
   `RUSTDOCFLAGS='-D warnings' cargo doc`. Rustdoc on every public item.
8. **No panic-catching.** A panic in a handler is a bug; catching it would hide the bug behind a
   degraded server, which is the silent-degradation shape III.11 rejects. The server logs and dies;
   the client restarts it.
9. **Machine safety.** This train's worktree has its **own `rust/target`** — a first full build of a
   new crate plus a Bevy-bearing workspace is expensive. Run `rust:check` **single-flight**; never
   fan it out across parallel agents. Pre-push mirrors it for any `rust/`-touching push, so push
   batches, not dribbles.
10. **`rust/Cargo.lock`:** after adding a dependency, refresh with `mise run rust:lock-refresh`
    (builds without `--locked`, preserving pins), commit the lock diff in the same PR, and let
    `rust:check`'s `--locked` legs be the gate. Run `cargo deny check` when the lock moves.

## 2. Charter decision 1 — the span mechanism

> **DECIDED: a CAS-safe span SIDE-TABLE emitted by the reader, stored as a pre-order `Vec` of
> `(FormPath, Span)` entries — no `HashMap`, no change to `SExpr`/`Atom`, no change to any existing
> error field. `read_all`/`read` keep their signatures; `read_all_spanned`/`read_spanned` are added
> beside them, and the existing entry points delegate and drop the table, so there is exactly ONE
> parser.**

### 2.1 The shape, and the parser change it actually requires

```rust
/// A byte range into the FILE (BOM included — `read_all` already re-bases
/// past a discarded BOM, `reader.rs:262-279`, and this table must agree).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Span { pub start: usize, pub end: usize }

/// A path from the top-level forest to one node: the top-level form's index,
/// then one child index per level down. `[3]` is the fourth top-level form;
/// `[3, 0]` is its head atom. Never empty.
pub type FormPath = Vec<u32>;

/// Pre-order spans for one file. Pre-order and lexicographic path order
/// COINCIDE, which is what makes `span_of` a binary search and what the
/// `spans_are_in_preorder` invariant test pins.
pub struct SpanTable { entries: Vec<(FormPath, Span)> }

impl SpanTable {
    #[must_use] pub fn span_of(&self, path: &[u32]) -> Option<Span>;
    #[must_use] pub fn innermost_at(&self, offset: usize) -> Option<(&[u32], Span)>;
    #[must_use] pub fn len(&self) -> usize;
    #[must_use] pub fn is_empty(&self) -> bool;
}
```

**What the parser already gives, stated exactly** (revision 1 overstated this, and an implementer
following its prose would have looked for a field that does not exist):

- Atom starts are **already computed and returned**: `lex_run` returns `(run, start)`
  (`reader.rs:497-514`) and `lex_string` takes `start` at the opening quote (`:406`). Atom ends are
  the scanner's position after the token. These are genuinely free.
- List starts are **not retained**. `parse_one`'s stack is `let mut stack: Vec<Vec<SExpr>> =
  Vec::new();` (`reader.rs:345`) — a stack of child-item vectors and nothing else. The `'('` arm
  (`:365-369`) pushes a bare `Vec::new()`; the `position` local (`:348`) is recomputed at the top of
  every iteration and discarded when the loop continues, so by the time the matching `')'` is
  reached in a later iteration the `(`'s offset is gone.

**Therefore Task 1 changes the stack's shape**, from `Vec<Vec<SExpr>>` to `Vec<(usize, Vec<SExpr>)>`
(the open-paren offset alongside the children), plus a live `FormPath` maintained by the same
push/pop. Small and entirely tractable — but a structural augmentation, not a read-only tap, and
the plan says so because an implementer budgeting "free reading" would be surprised.

### 2.2 Why this shape, and what was rejected

| Candidate | Verdict |
|---|---|
| **Pre-order `Vec` of `(FormPath, Span)`** | **CHOSEN.** CAS-safe by construction (`SExpr` untouched). Deterministic iteration by construction — no hash ordering near an output. Path keys survive cloning and moving of subtrees, and they are printable ("form 3.1.2"). Pre-order + lexicographic coincidence gives O(log n) lookup with no index structure. |
| Bare pre-order `Vec<Span>` (no paths) | Rejected: correspondence depends on the consumer performing the identical pre-order walk, and breaks silently the moment a subtree is cloned or reordered. |
| `HashMap<FormPath, Span>` | Rejected: same information, introduces a hash-ordered container into the diagnostics path. |
| Spans threaded through `SExpr`/`Atom` | Rejected for wave 1 (charter agrees). ~30k lines of consumers pattern-match `SExpr`; `canonical_bytes(&SExpr)` (`canonical_ast.rs:33`) walks it directly, so any shape change requires re-proving §5.6 from scratch rather than proving it untouched. |
| A parallel `SpannedSExpr` tree | Rejected: two ASTs that can drift, and every consumer needs a conversion. |
| LSP-side re-location by matching error prose | Rejected as a mechanism, and banned by sentinel 7.2. §6.2's locator is driven by `ErrorIdentity` — typed data minted by the loader. |

### 2.3 What errors gain — typed identity at the source (§0.1 finding 1)

Wave 1 adds **one shared concept** to `babylon-bsl`, not a field per error type:

```rust
/// WHAT the loader is complaining about, as data a locator can find in a
/// parsed tree. Never prose. Populated at the raise/conversion seam, in the
/// crate that knows its own errors.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ErrorIdentity {
    /// A bare symbol: a binding name, an intrinsic name, an element name.
    Name(String),
    /// A field qname, e.g. `social-class/wages`.
    Field(String),
    /// A rule id, e.g. `control-ratio/c01-prisoner-census`.
    RuleId(String),
    /// An enum type and (optionally) one of its members.
    Enum { enum_type: String, member: Option<String> },
    /// A scenario-local node name.
    NodeLocal(String),
    /// A scenario edge, by type and endpoints.
    Edge { edge_type: String, from: String, to: String },
    /// A keyword operand, e.g. `:fuel` — located by keyword position.
    Keyword(String),
    /// A form head plus a zero-based operand index (grammar-arity errors).
    Operand { form: String, index: usize },
    /// More than one candidate; the locator refuses to guess and reports
    /// all of them as related information.
    Ambiguous(Vec<ErrorIdentity>),
}
```

Two producers, both **wildcard-free** so the compiler enforces exhaustiveness — a new error variant
breaks the build rather than silently defaulting to file level:

- `pub fn identity_of(err: &LoadError) -> Option<ErrorIdentity>` in `babylon-bsl`, a `match` over
  every wrapped type's variants (§6.2's roster).
- `pub identity: Option<ErrorIdentity>` on `ScenarioError`, populated by **every** conversion impl
  and helper — the seven construction sites of Task 2.3 — instead of being thrown away.

`ScenarioError` also gains `pub position: Option<usize>` so `From<ReadError>` stops destroying a
structured byte offset (`scenario.rs:89-99`).

This is deliberately *not* "thread `FormPath` through twelve error types": the loader names the
thing, the server finds it. Threading paths is a wave-2 upgrade for cases where a name is genuinely
ambiguous within one file.

### 2.4 The CAS §5.6 byte-identity proof obligation — a PER-COMMIT gate

`SExpr` is unchanged, so `canonical_bytes` is unchanged *by construction*. That argument is not
evidence. **The pre-existing pins are the independent oracle** — fixed before the refactor,
re-asserted after it — and they are what actually protects against Task 1 silently changing what
the reader produces:

```bash
cd rust
cargo test -p babylon-bsl --locked canonical_ast          # §5.6: 421 bytes + both digests
                                                          # (canonical_ast.rs:391,481,574)
cargo test -p babylon-bsl --locked the_worked_examples_421_bytes_and_digests_are_untouched
                                                          # r9_chapters.rs:3049-3075
cargo test -p babylon-tick --locked                       # tick_goldens.rs
cargo test -p babylon-bsl --locked                        # the whole crate, incl. the corpus
```

Pinned values, quoted so a reviewer can check them without running anything
(`r9_chapters.rs:3059-3074`): **421 bytes**;
`sha256(canonical_bytes) = 8a62d0b5724de24ec36ea0dfb3f4d120a63d90a56bad2a4605e645368f304da3`;
`rules_hash_of([worked]) = 4e6fbf64c771bd8e2f7874b4c906d0330458ba965911d00a9a731ea8a724238f`.

`tick_goldens.rs` pins **16** before/after hash pairs — `rg -c 'fn .*_hashes_are_pinned'` = 16, and
`rg -o '"[0-9a-f]{64}"' | wc -l` = 32 (18 `#[test]` fns total; two are ordinal-order tests, not
hash pairs). Revision 1 said 13, inherited from a survey that counted an early `include_str!` block
rather than the tests, and repeated it four times. The gate itself was never affected —
`cargo test` runs what exists — but a reviewer scripting a count check against "13" would have got
a false failure.

**And one honest addition, because the obvious extra check is nearly worthless.** A corpus row
asserting `read_all(src) == read_all_spanned(src).0` is **close to tautological** once Task 1.3's
delegation lands: `read_all` is *defined as* the spanned path with the table dropped, so the
assertion compares a function to itself through tuple projection. It can catch miswired glue
(returning `.1`, forgetting the BOM re-base) and nothing else — there is no independent oracle
behind it. It is kept at that honest weight, and the real broad-corpus protection is a **pre/post
golden-AST digest**, captured in the RED commit *before* the refactor and asserted after:

- Task 1.1 (RED, pre-refactor) computes `sha256(format!("{:#?}", read_all(src)?))` for every `.bsl`
  and `.bscn` in the tree and writes them into the test as pinned constants, using the **current**
  `read_all`.
- Task 1.4 (GREEN, post-refactor) asserts every digest is unchanged.

That covers all 63 content files (25 `.bsl` + 37 scenario `.bscn` + 1 prelude `.bscn`, each count
from `find`/`ls`), of which only the §5.6 example and the 16 tick-golden scenarios were covered
before. It is cheap, it is a genuine before/after oracle, and it is the check the corpus row was
pretending to be.

> **DECIDED: `lsp-server` (rust-analyzer's transport crate) + `lsp-types`, synchronous,

| Axis | `lsp-server` + `lsp-types` | `tower-lsp` |

A large permanent tree for a stdio server. |
| **Determinism discipline** | One thread, one request at a time, replies in receipt order. "Same input sequence ⇒ same output sequence" is a property of the loop's shape, not of a scheduler. | `async` + a work-stealing runtime: correct, but interleaving is a runtime property. |
| **Lifecycle (spec digest §2)** | `Connection::initialize` implements the exact handshake; `shutdown`/`exit` are ours to honor explicitly — the `-32002`-before-`initialize` rule becomes a line of our code with a test on it. | Handles the parts we want to assert on. |
| **Maintenance** | Lives in the `rust-lang/rust-analyzer` tree; deliberately minimal and stable because rust-analyzer depends on it. | Third-party, intermittent release cadence. |
| **Cost accepted** | ~200 lines of hand-written dispatch, push notifications via `Connection::sender`. No per-capability trait, no built-in cancellation plumbing. | Would have given both for free. |
| **Shared** | Both use `lsp-types`, so the type layer — the expensive part to migrate — is identical either way. A later harness switch is transport-only. | — |

Licenses: `lsp-server` is `MIT OR Apache-2.0`, `lsp-types` is `MIT`; both classes are on
`rust/deny.toml`'s permissive allowlist (the `allow` array runs `:40-62`; `"MIT"` at `:45`,

worktree** — `cargo deny check` in Task 5.2 is what settles it, and a refusal there is a STOP, not
a waiver (§10 B10).

**Transport:** stdio. One binary, `bsl-ls`, from a lib+bin crate: the lib holds everything testable,

### 4.2 Why TOML, and what was rejected

- **TOML.** Rust-native (`toml` crate; its backend `toml_edit` is already in the lock at
  `Cargo.lock:5088,5100`) **and** Python-native with zero new dependencies — `tomllib` is stdlib on
  3.11+, and this repo pins 3.12. Both readers get it free; array-of-tables diffs one row at a time.
- **YAML** — rejected: the repo's YAML estate is Python-side; the Rust side would need a new
  serde-yaml tree for no gain.
- **A new BSL top-form** — **rejected on constitutional grounds.** Minting a form tag is a
  §5.2/`RESERVED_FORM_TAGS` change and amendment-adjacent; the manifest is build metadata, not

**The protocol harness's hang discipline** (the gap revision 1 left; there is no in-repo precedent
to copy — `rg -l 'CARGO_BIN_EXE|Stdio::piped' rust/crates` returns nothing, so this is the
workspace's first subprocess-IPC test and its pattern must be written out):

- The child is spawned with `Stdio::piped()` on stdin/stdout/stderr and owned by a **`ChildGuard`
  newtype whose `Drop` calls `kill()` + `wait()`**, so a panicking or failing test never orphans a
  server process.
- A **reader thread** owns the child's stdout, parses `Content-Length` frames, and sends each
  parsed message over a `std::sync::mpsc::channel`. The test body never blocks on the pipe directly.
- The test body waits with **`rx.recv_timeout(Duration::from_secs(30))`**. A timeout kills the
  child, drains and prints its stderr, and fails with "server did not answer `<method>` within 30s"
  — a fast, legible failure instead of a hung CI job.
- **`const MAX_FRAMES: usize = 64;`** bounds the loop's iterations (Power-of-10 rule 2). The timeout
  bounds each individual wait. Both are required: `MAX_FRAMES` alone never fires on a server that
  writes nothing, because the loop is stuck *inside* an iteration.
- Determinism note: 30s is a **watchdog**, never a performance assertion. It can only convert a hang
  into a failure; no test passes or fails on how *fast* the server answered. This is the distinction
  the P15 Gauntlet lesson ("wall-clock tests = determinism poison") actually draws, and it is
  recorded next to the constant so nobody later "tightens" it into a latency gate.

## 6. The diagnostics contract

### 6.1 Capabilities advertised in wave 1 — exactly these

```jsonc
{
  "textDocumentSync": { "openClose": true, "change": 1 },        // Full
  "diagnosticProvider": {
    "identifier": "bsl",
    "interFileDependencies": true,                                // §0.1(2)
    "workspaceDiagnostics": true
  },
  "workspace": { "workspaceFolders": { "supported": true, "changeNotifications": true } }
  // positionEncoding omitted -> UTF-16, the mandatory default (spec digest §2)
}
```

**Full, not Incremental**: the loader re-reads the whole file on every change regardless, the
largest file in the estate is 24 KB (`content/scenarios/consciousness-ternary-conformance.bscn`)
against a ~440 KB total content estate, and Full deletes a class of position-mapping bugs.
Incremental is a wave-2 optimization to be taken only against a measurement.

Push **and** pull: push is the universally-supported floor and costs nothing once we recompute on
change; `workspace/diagnostic` is the capability that serves a coding agent, giving one synchronous
"entire current error state" call after an edit.

`resultId` is `sha256` over the ordered `(uri, bytes)` tuples of the set plus the manifest bytes —
**deterministic across restarts**, so `unchanged` reports stay correct after a server restart. A
monotonic counter would have been state, and wrong.

Dynamic registration of `workspace/didChangeWatchedFiles` for `**/*.{bsl,bscn}` and
`**/content-sets.toml` (the spec's own argument against rolling our own watcher). If the client does
not support dynamic registration, the server logs a `window/logMessage` warning stating that on-disk
edits outside open documents are picked up only at pull time — loud, not silent.

### 6.2 The locator, and the precision policy

For each loader error the server produces exactly one `Diagnostic`:

- `code` = `spec_code()` verbatim (`LoadError::spec_code`, `rule_pipeline.rs:166-188`;
  `ScenarioError.code`; `LexCode::spec_code`, `reader.rs:187-207`; and — new in Task 3 —
  `PrepareError::spec_code`), or absent where the loader itself declares no code. Never invented.
- `source` = `"bsl"`; `severity` = Error for refusals, Warning for `lint_defaults` findings
  (`rule_pipeline.rs:318`), Information for the server's own "no content set declares this file"
  notice.
- `data` = `{ family, precision }`. **`d_records` is NOT in wave 1** — see the carve-out note below.
- `range` by this policy:

| Family | Wave-1 precision | Mechanism |
|---|---|---|
| `E-LEX` (13 codes) | **Exact** | `ReadError.position` → `SpanTable::innermost_at` → the token's full span. Already BOM-re-based (`reader.rs:276-279`). |
| Any error carrying an `ErrorIdentity` (§2.3) | **Form** | One of four locator strategies (below) → `SpanTable::span_of`. Unique match ⇒ that span. **Ambiguous ⇒ file-level plus one `relatedInformation` per candidate.** Absent ⇒ file-level. |
| `E-TYPE` (15 codes) | **File** | `TypeError` is `{code, message}` with no struct variants at all (`typecheck.rs:81-85`) — nothing to name. Wave 2 gives it identity at the raise site. |
| Prose-only variants (`Malformed{message}` in six modules; `DomainError::Undeterminable{candidates}`) | **File** (Undeterminable ⇒ file + related) | By construction: the loader has no single token to name. |
| `E-EVAL` reached with no live session | **File**, distinct message | The loader's loud `require_graph` driver error (`evaluator.rs:465`) surfaces as "requires a live session (#532)", never as a pretend result. |

**Four locator strategies — not 52 predicates.** The `ErrorIdentity` enum (§2.3) collapses the error
surface into a handful of shapes, so the server implements four generic strategies and the
per-variant work lives in `babylon-bsl`'s `identity_of` match:

| Strategy | Finds | Serves |
|---|---|---|
| `by_atom(token)` | the unique atom equal to `token` | `Name`, `NodeLocal`, `RuleId` |
| `by_qname(token)` | the unique qname atom equal to `token` | `Field` |
| `by_head_and_operand(head, token)` | a `List` whose head is `Symbol(head)` containing `token` | `Enum`, `Edge` |
| `by_keyword_operand(kw)` / `by_operand_index(form, i)` | the operand after `:kw`, or operand `i` of form `head` | `Keyword`, `Operand` |

**The `identity_of` map is exhaustive by compiler, not by test.** The reconnaissance is done: the
wrapped error types expose **52 struct variants** across nine modules — `declarations.rs` 7,
`bindings.rs` 10, `grammar.rs` 8, `mod_anchors.rs` 4, `domain.rs` 4, `scope.rs` 5,
`bound_checker.rs` 6, `material_basis.rs` 2, `vocabulary.rs` 6 — plus `typecheck.rs`, which has
none. Of the 52, **45 carry a locatable identity field** and 7 are prose-only (`Malformed{message}`
×6, `DomainError::Undeterminable{candidates}` → `ErrorIdentity::Ambiguous`). The roster, with the
field that drives each:

| Variant | Field → identity |
|---|---|
| `DeclError::Duplicate{name, what}`, `ReservedIntrinsicName{name, reason}`, `SignatureMismatch{name, detail}` | `name` → `Name` |
| `DeclError::KernelDisagreement{field, …}`, `EnumKindShapeViolation{field, …}`, `UnknownEnumRegistryType{field, …}` | `field` → `Field` |
| `BindingError::{BadCycleLength, ForwardOrSelfReference, OptionalOnExpr, ReservedName, DuplicateName, OptionalWithoutDefault, Unresolved, UnregisteredMetric}{name, …}` | `name` → `Name` |
| `BindingError::UnknownKeyword{keyword}`, `AnchorError::UnknownKeyword{keyword}` | `keyword` → `Keyword` |
| `GrammarError::WrongEnumKind{form, operand, …}`, `Arity{form, found, expected}`, `ArithmeticArity{operator, found}` | → `Operand{form, index}` |
| `GrammarError::StrengthFieldInit{field}`, `FieldInitOwnerMismatch{field, …}` | `field` → `Field` |
| `GrammarError::NotInClosedSet{symbol, …}`, `StringInExpressionPosition{literal}` | → `Name` |
| `GrammarError::Vocabulary{form, error}` | delegate to the wrapped `VocabularyError`, else `Operand` |
| `AnchorError::{NoSystemForRule, UnregisteredAnchorSystem}{rule_id, …}`, `BoundError::BoundExceeded{rule_id, …}` | `rule_id` → `RuleId` |
| `DomainError::DomainDisagreement{declared, found}`, `SelfInGraphDomain{reference}` | → `Name` |
| `ScopeError::{ForeignFieldOutsideBody, AmbiguousForeignField}{binding, …}` | `binding` → `Name` |
| `ElementNameError::{ReservedElementName, ElementNameCollision, NameOutsideItsBody}{name}` | `name` → `Name` |
| `BoundError::{MissingMaxMembers, MemberListOverCeiling}{hyperedge_type, …}`, `MissingCeiling{queried_type}` | → `Enum{enum_type, member: None}` |
| `BoundError::UndeclaredIntrinsic{name}` | `name` → `Name` |
| `MaterialBasisError::FuelOutOfRange{declared}` | → `Keyword(":fuel")` |
| `VocabularyError::{UnknownEnumType, WrongEnumKind, UnknownEnumMember}{enum_type, member, …}` | → `Enum` |
| `VocabularyError::RenderingCollision{symbol, …}`, `InvalidRendering{member, …}`, `UnknownFieldOwner{segment}` | → `Name` / `Enum` |
| `*::Malformed{message}` (×6), `DomainError::Undeterminable{candidates}` | `None` / `Ambiguous` — File tier |

Because the match is wildcard-free, adding an error variant later is a **compile error**, not a
silent file-level downgrade — the strongest available form of the exhaustiveness guarantee, and
stronger than the conformance-row check revision 1 implied.

**The banned route, and why there is no carve-out.** The server must never derive a location — or
anything else — by scanning an error message's text. Sentinel 7.2 enforces this with **no
exceptions**. Revision 1 required `data.d_records` to hold "the `D\d+` tokens already present in the
loader's own message", which is a text scan of that message by definition and would have made Tasks
6 and 7 unsatisfiable in the same PR. **Resolved by dropping the feature, not by weakening the
guard**: D-record surfacing moves to wave 2 (phase 5, hover), where it is implemented properly — a
`pub fn d_records_for(code: &str) -> &'static [u16]` static table in `babylon-bsl`, sync-guarded
against the register the same way the grammar is. The wave-1 diagnostic omits the field entirely
rather than shipping an always-empty one.

Diagnostics are emitted in a declared total order — `(range.start, range.end, code, message)` — so
serialization is stable and the determinism row is meaningful.

### 6.3 What a per-file pass actually runs

- **`.bscn` (scenario):** `load_scenario` (or `load_scenario_with_prelude` when the manifest
  declares a prelude, `scenario.rs:387`) into a throwaway store.
- **`.bscn` (prelude — no `(scenario …)` wrapper):** identified by the manifest, falling back to
  sniffing for a top-level `scenario` head. Loaded as the prelude half of every set naming it, so
  its diagnostics are the union over its consumers, deduplicated by the total order.
- **`.bsl`:** resolve the content set from the manifest → Task 3's `diagnose_content_set` → the full
  staged pipeline against the scenario's registries.
- **`.bsl` with no manifest row:** run only the declaration-independent stages (read,
  `split_content`, surface/`:material-basis`, static shape) and emit the Information notice naming
  the missing row. Diagnostics from stages that cannot run are **not emitted** — absence, never a
  guess. That notice doubles as a manifest-drift alarm.

**Concrete git mechanics.** The stack is a *chosen* order, not a compile dependency — verified: PR B
wraps `ScenarioError` as a whole in `PrepareError::Scenario`, so it would compile against today's
two-field struct without PR A. Nothing in the code will catch a wrong base, which is exactly why it
is written out:

```bash
# PR A
git checkout dev && git pull && git checkout -b feature/652-bsl-span-table
# PR B — branch from A's TIP, not from dev
git checkout feature/652-bsl-span-table && git checkout -b feature/652-structured-load-seam
# PR C1 from B's tip, C2 from C1's tip, E from C2's tip — same pattern.
# PR D is independent:
git checkout dev && git checkout -b feature/652-bscn-grammar-d93
```

- Open each PR with `--base` set to its parent branch (`gh pr create --base feature/652-…`), so the
  diff a reviewer sees is that PR's own work, not its ancestors'.
- **When a parent merges**, retarget the child to `dev` and rebase it:
  `gh pr edit <child> --base dev && git rebase --onto dev <old-parent-branch> <child-branch>`.
  Do this **before** requesting the child's final review, so CI runs against the real merge base.
- **Never `--delete-branch` a parent while a child still targets it** (#193: it closes rather than
  merges the child). `mise run pr:merge` refuses this by construction — do not work around it.
- Merge order: A → B → C1 → C2 → E, each after its parent is on `dev` and the child is rebased. D
  whenever it is green.

Commit-message scopes: `feat(bsl)`, `feat(tick)`, `feat(ls)`, `test(ls)`, `docs(bsl)`,
`chore(rust)`. Conventional commits, `Co-Authored-By` trailer on every one.
