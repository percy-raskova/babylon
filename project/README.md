# Project corpus

<!-- V4-PROJECT-CORPUS:START -->

The `project/` tree is Babylon's historical planning and design corpus. Its
programs, plans, notes, and audits preserve why earlier work made sense. They
are dated evidence, not a control surface for current status.

Linear is the sole portfolio authority for scope, status, priority,
dependencies, Horizon, milestones, schedule, and current work. GitHub remains
the delivery and history surface for source, pull requests, reviews, and
historical evidence.

## Catch up in this order

1. Read [the Constitution](../CONSTITUTION.md) for product law and
   [the North Star](../NORTH_STAR.md) for orientation.
2. Read the
   [Linear project](https://linear.app/percy-raskova/project/babylon-v1-playable-political-economy-299b037e7feb)
   and
   [Roadmap Charter](https://linear.app/percy-raskova/document/babylon-v4-roadmap-charter-2c67d2898306)
   for the current portfolio and status.
3. Read [the roadmap mirror](roadmap.md) for a repository explanation of the
   nine-gate order. Its dates are provisional and its statuses are not live.
4. Read [the architecture truth record](../ai/architecture.yaml) for evidence-
   backed current-versus-planned implementation truth.
5. Use [the state ledger](../ai/state.yaml) only for chronological
   implementation evidence.

## Historical directories

- `programs/` records completed and superseded delivery programs.
- `plans/` records dated implementation proposals and review context.
- `notes/` records investigations, audits, and unresolved observations from
  their stated dates.
- `research/` records research questions and source work. Research is not an
  implementation commitment until a Linear-owned mechanic pulls it.

The old progress-report chains are historical. Django/React status:
historical_client_record. Ratatui/TUI status: retired. Project #7 status:
frozen_migration_input. Project #8 status: frozen_migration_input. None of
these records defines Babylon v1 or chooses the next task.
