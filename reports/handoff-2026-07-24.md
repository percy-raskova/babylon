### Worktree gotchas hit today (add to your muscle memory on the new machine)

- **`uv run` in a worktree rewrites `uv.lock`.** `[tool.uv.sources]` points at
  `../hypergraph-rs` — from `.claude/worktrees/<name>` that path doesn't exist, so `uv run`
  re-resolves and *prunes the lockfile* (the mypy pre-commit hook then "fails" because it
  modified a tracked file). Fix: `UV_NO_SYNC=1 mise run commit -- ...` (or `uv run --no-sync`)
  for any hook-driving command in a worktree. Re-resolution still requires the real sibling
  checkout at `/home/user/projects/game/hypergraph-rs`.
- **Sentinel checks resolve the wrong venv from a worktree.** Always
  `PYTHONPATH="$PWD/src" uv run python tools/sentinel_check.py ...` or use the `mise run`
  tasks, which set it correctly. Running bare gave output from the MAIN checkout's tree —
  extremely confusing mid-debug.
- A stale `VIRTUAL_ENV` (main checkout's `.venv` activated in your shell) leaks into
  pre-commit hooks. `env -u VIRTUAL_ENV` when in doubt.
